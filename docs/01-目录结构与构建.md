## 1. 本机开发环境（已就绪）

| 工具 | 路径 | 说明 |
|---|---|---|
| JDK 17 | `E:\AndroidDev\jdk-17.0.20.1+1` | AGP 8.12 要求 JDK 17，**不能用系统的 JDK 26** |
| Gradle 8.13 | `E:\AndroidDev\gradle-8.13` | 直接调用 `bin/gradle`，未使用 wrapper（省一次下载） |
| Gradle 缓存 | `E:\AndroidDev\gradle-home` | 所有依赖缓存在 E 盘，不占 C 盘 |

| adb | `D:\Android\SDK\platform-tools\adb.exe` | |

> 为什么装到 E 盘：C 盘只剩 30G，Android 构建缓存动辄 2~3G，装 E 盘（193G 可用）更稳。

## 3. 常用命令

```bash
# 编译 Debug（约 40~90 秒，首次下载依赖更久）
gradle assembleDebug --no-daemon

# 编译 Release（R8 混淆 + 签名）
gradle assembleRelease --no-daemon

# 只检查编译错误，不出包（更快）
gradle compileDebugKotlin --no-daemon

# 清理
gradle clean --no-daemon

# 看依赖树
gradle :app:dependencies --configuration debugRuntimeClasspath --no-daemon
```

产物位置：

```
app/build/outputs/apk/debug/app-debug.apk
app/build/outputs/apk/release/app-release.apk
```

安装 / 启动 / 截图：

```bash
ADB="/d/Android/SDK/platform-tools/adb.exe"
"$ADB" install -r app/build/outputs/apk/release/app-release.apk
"$ADB" shell am start -n com.zhuri.daybyday/.MainActivity
"$ADB" exec-out screencap -p > shot.png
"$ADB" logcat -d -t 200 | grep -i "AndroidRuntime\|zhuri"
```

## 5. 依赖与构建配置要点

```kotlin
android {
    namespace = "com.zhuri.daybyday"
    compileSdk = 36
    defaultConfig { minSdk = 23; targetSdk = 36; versionCode = 5; versionName = "1.3" }
    buildFeatures { compose = true }
    compileOptions {
        isCoreLibraryDesugaringEnabled = true
        sourceCompatibility = JavaVersion.VERSION_17
        targetCompatibility = JavaVersion.VERSION_17
    }
    kotlinOptions { jvmTarget = "17" }
    buildTypes {
        release { isMinifyEnabled = true; isShrinkResources = true; proguardFiles(...) }
    }
}
```

- Compose 编译器用 **Kotlin 2.x 自带的 `org.jetbrains.kotlin.plugin.compose`**，不再写 `composeOptions.kotlinCompilerExtensionVersion`。
- **minSdk 23 + core library desugaring**：`java.time` 在 Android 6~7 上由 `desugar_jdk_libs` 提供，因此能覆盖 MuMu 6 等旧模拟器；APK 同时带 v1/v2 签名。
- 仓库：`google()` + `mavenCentral()` + 阿里云镜像兜底（`maven.aliyun.com/repository/public`）。
- 未开启 configuration cache（首次构建更稳）。

## 6. 签名

Release 包使用项目内 keystore（仅本地自用，勿公开分发）：

```
文件：signing/zhuri-release.jks
别名：zhuri
密码：zhuri2026
有效期：10000 天
```

配置写在 `app/build.gradle.kts`，`assembleRelease` 直接产出可安装的签名包。

## 7. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `Unsupported class file major version 70` | 用了系统 JDK 26 | 重新 export `JAVA_HOME` 指向 JDK 17 |
| `SDK location not found` | 缺 `local.properties` | 写入 `sdk.dir=D:\\Android\\SDK` |
| `Could not resolve androidx.compose.*` | 网络 / 仓库顺序 | 检查 google() 是否在前，或加阿里云镜像 |
| 首次构建卡在 `Downloading` | 依赖体积大（约 300MB） | 正常，等一次；之后走缓存 |
| 安装报 `INSTALL_FAILED_OLDER_SDK` | 设备低于 Android 6.0 | 换 API 23+ 的模拟器或真机；MuMu 6 已覆盖 |
| 抽屉弹出被键盘挡住 | 缺 `imePadding()` | 见 `EditorSheet` 根布局 |

## 8. 本机踩过的坑（已解决，别再踩一遍）

### 8.1 项目路径含中文，AGP 直接拒绝构建

```
Failed to apply plugin 'com.android.internal.application'.
> Your project path contains non-ASCII characters.
```
解决：`gradle.properties` 里加 `android.overridePathCheck=true`。
本项目纯 Kotlin + Compose，没有 NDK / 原生代码，路径含中文不会影响产物。

### 8.2 GitHub 不可达，官方 JDK 下载失败

Adoptium 的下载会 302 到 GitHub，直接超时。改用清华镜像：
`https://mirrors.tuna.tsinghua.edu.cn/Adoptium/17/jdk/x64/windows/`

### 8.3 Google 官方 SDK 下载只有 250KB/s

系统镜像 1.7G 要下一个多小时。腾讯云镜像 11MB/s：
`https://mirrors.cloud.tencent.com/AndroidSDK/sys-img/google_apis/x86_64-35_r09.zip`
（其余包同理，把 `https://dl.google.com/android/repository/` 换成
`https://mirrors.cloud.tencent.com/AndroidSDK/` 即可）

### 8.4 avdmanager 认不出手动放入的系统镜像

手动解压的系统镜像没有 `package.xml`，`avdmanager create avd -k ...` 会报
`Package path is not valid`。解决办法：**不用 avdmanager，直接写 AVD 配置文件**。

`C:\Users\<用户>\.android\avd\zhuri.ini`
```ini
avd.ini.encoding=UTF-8
path=C:\Users\<用户>\.android\avd\zhuri.avd
path.rel=avd\zhuri.avd
target=android-35
```

`C:\Users\<用户>\.android\avd\zhuri.avd\config.ini` 关键字段：
```ini
AvdId=zhuri
abi.type=x86_64
hw.cpu.arch=x86_64
hw.cpu.ncore=6
hw.ramSize=3072
hw.lcd.width=720
hw.lcd.height=1600
hw.lcd.density=320
image.sysdir.1=system-images/android-35/google_apis/x86_64/
tag.id=google_apis
skin.name=720x1600
skin.path=_no_skin
hw.keyboard=yes
```
`image.sysdir.1` 相对于 SDK 根目录。写好后 `emulator -list-avds` 就能看到。

### 8.5 无窗口模拟器性能太差，SystemUI 反复 ANR

- 用 `-gpu swiftshader_indirect` 时**不要**开 1080×2400 + 2G 内存，SystemUI 会卡到弹
  「System UI isn't responding」，挡住所有点击。改成 720×1600 + 3072MB + 6 核后正常。
- 关掉系统动画再截图：`settings put global window_animation_scale 0`（另两项同理）。

### 8.6 模拟器内写数据文件

Release 包不可 `run-as`，需要 root：
```bash
adb root
adb push zhuri_data.json /data/data/com.zhuri.daybyday/files/zhuri_data.json
adb shell "chown u0_a209:u0_a209 /data/data/com.zhuri.daybyday/files/zhuri_data.json"
```
Git Bash 下调用 adb 必须 `export MSYS_NO_PATHCONV=1`，否则 `/data/...` 会被转成 Windows 路径。

### 8.7 点击坐标总是不准

`adb shell input tap` 用**真实像素**，而截图在预览里会被缩放。定位元素请用：
```bash
adb shell uiautomator dump /sdcard/ui.xml && adb pull /sdcard/ui.xml
```
从 XML 的 `bounds="[x1,y1][x2,y2]"` 读中心点。
