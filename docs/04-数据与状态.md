# 04 · 数据与状态

> 读这一篇的目的：知道数据存在哪、长什么样、什么时候写盘、怎么加字段不炸旧数据。
> 上层入口：`../AGENTS.md` ｜ 相关：`02-功能规格.md`

---

## 1. 存储位置

```
/data/data/com.zhuri.daybyday/files/zhuri_data.json      ← 主文件
/data/data/com.zhuri.daybyday/files/zhuri_data.bak.json   ← 损坏时的备份
```

不申请存储权限，不写外部存储，不上传。卸载即彻底删除。

## 2. 文件格式（v1）

```json
{
  "version": 1,
  "tasks": [
    {
      "id": "a1b2c3",
      "title": "读 20 页书",
      "note": "第 3 章，做笔记",
      "startDate": "2026-11-06",
      "repeat": "DAILY",
      "weekDays": [1, 3, 5],
      "monthDay": 1,
      "time": "08:00",
      "createdAt": 1762406400000
    }
  ],
  "done": ["a1b2c3|2026-11-06", "a1b2c3|2026-11-07"],
  "entries": [
    {
      "id": "e9f8d7",
      "title": "傍晚的风",
      "content": "下班路上闻到桂花，绕远走了十分钟。",
      "date": "2026-11-07",
      "createdAt": 1762511040000,
      "updatedAt": 1762511040000
    }
  ]
}
```

- `repeat`：`NONE | DAILY | WEEKLY | MONTHLY`，未知值按 `NONE` 处理（向前兼容）。
- `weekDays`：1=周一 … 7=周日，仅 WEEKLY 有意义，其它类型忽略。
- `time`：`HH:mm` 或 `null`。
- `done`：字符串数组，`<taskId>|<yyyy-MM-dd>`。用数组而非对象，方便增量去重。
- `entries`：笔记数组。正文为空的条目不写入、读取时丢弃；没有该字段时按空数组处理（向前兼容）。

## 3. 写入时机

| 触发 | 行为 |
|---|---|
| 新增 / 编辑 / 删除任务 | 立即写盘（`Dispatchers.IO`，事务式：写 tmp → rename） |
| 勾选 / 取消完成 | 立即写盘 |
| App 冷启动 | 只读，不写 |
| 后台被杀 | 无待写数据（因为每次变更都已落盘） |

**为什么每次变更都写**：数据量极小（几百条 < 30KB），一次写盘 < 3ms，换来「永不丢数据」。
写盘用单线程 `Dispatchers.IO.limitedParallelism(1)` 串行化，避免并发覆盖。

## 4. 原子写入实现要点

```kotlin
val tmp = File(dir, "zhuri_data.tmp")
tmp.writeText(json)
if (!tmp.renameTo(file)) { file.delete(); tmp.renameTo(file) }
```
断电 / 崩溃时最多丢最后一次操作，不会产生半个 JSON。

## 5. 状态流

```
TaskRepository
├── val tasks:   StateFlow<List<Task>>       // 只读，UI collect
├── val done:    StateFlow<Set<String>>      // 只读
├── val entries: StateFlow<List<DiaryEntry>> // 笔记，只读
└── fun add / update / delete / toggle       // 任务写入口
    fun addEntry / updateEntry / deleteEntry // 笔记写入口
```

- 单例由 `ZhuriApp` 创建，`Root()` 通过 `LocalContext` 取 `application as ZhuriApp`。
- UI 全部用 `collectAsStateWithLifecycle()` 订阅（`lifecycle-runtime-compose`）。
- **派生数据不存**：某天的应做列表、完成度、streak、笔记分组与写作统计全部在
  `remember(tasks, done, entries, today)` 里现算。这样任何写操作都天然一致，不需要「同步两份状态」。
- 笔记的写作统计在 `Root` 里用 `remember(entries, today)` 算一次，同时给「笔记」页和「总结」页，
  避免两页各算一遍。

## 6. 笔记数据（v1.3）

同一个 `zhuri_data.json` 新增 `entries` 数组，旧版本没有该字段时按空数组读取：

```json
{"id":"uuid","title":"傍晚的风","content":"正文","date":"2026-11-07","createdAt":0,"updatedAt":0}
```

- `title` 可空；`content` 必填，读取时跳过空白正文。
- `date` 是归属日，可补记最近 7 天；统计按它而不是 `createdAt` 归日。
- `createdAt` 用于组内排序与显示 `HH:mm`，`updatedAt` 只用于「已编辑」标记。
- 字数按去除空白后的字符数统计；新增、修改、删除仍走同一份原子写入文件，不新增数据库和权限。

## 7. 版本升级策略

- `version` 字段用于判断是否需要迁移。
- 加字段：给默认值即可，读取时 `optString / optInt` 容错，**不升 version**。
- 改语义（如把 `done` 从数组换成对象）：升 version，在 `load()` 里做一次性迁移，迁移成功后立刻回写。
- 读失败（JSON 异常、字段类型错）：把原文件改名成 `.bak.json`，以空数据启动，绝不让 App 崩在启动页。

## 8. 为什么不用 Room

- 数据量：几百条任务、几年完成记录、笔记正文，全量加载 < 1MB，内存完全放得下。
- 查询：所有查询都是「某天的发生集合」，用 `filter { it.occursOn(d) }` 一次遍历，微秒级。
- 代价：Room 会引入 KSP（编译变慢、构建链条变长）和 schema 迁移负担。
- 结论：**JSON 文件 + 全量内存**在这个体量下更快、更简单、更不容易出错。数据量超过 5000 条再考虑迁移。

## 7. 分类字段（v1.5）

`zhuri_data.json` 增加 `categories` 字符串数组，与 `entries` 并列：

```json
{"categories":["想法","生活","工作","学习","其他"]}
```

每条笔记的 `category` 直接存分类名（字符串）。旧版本存的是枚举名（IDEA/LIFE/…），
读取时通过 `normalizeCategory` 自动映射为中文名；找不到对应分类时归入第一个分类。
